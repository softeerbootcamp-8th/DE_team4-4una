# 06. 품질 검증 실패를 전체 실패가 아니라 행 단위 격리로 처리한다

> 가용성과 정확성이 정면으로 충돌하는 지점에서 양쪽을 모두 지킨 사례입니다.

← [의사결정 목록](README.md)

## 트리거

Current Score는 서빙 테이블에 직접 쓰입니다. 품질 검증에서 일부 행이 실패했을 때 어떻게 할지 정해야 했습니다.

## 근본 원인

가용성과 정확성이 정면으로 충돌하는 지점입니다. 한쪽을 전부 택하면 다른 쪽이 무너집니다.

| 극단적 선택 | 결과 |
| --- | --- |
| 한 행이라도 실패하면 전체 실패 | 서빙 데이터가 갱신되지 않는다. 정상 행 99.9%가 오래된 값으로 남는다 |
| 검증 실패를 무시하고 전부 적재 | 잘못된 점수가 그대로 노출된다. 경로 추천이 오염된다 |

## 결정

두 가지를 함께 적용합니다.

1. **행 단위 격리** — 잘못된 행만 `current_segment_comfort_score_quarantine`으로 분리하고, 정상 행은 계속 서빙한다.
2. **서킷브레이커** — 실패율이 임계치를 넘으면 적재 자체를 중단한다.

격리만 두면 상류가 크게 망가졌을 때 오염이 조용히 확산됩니다. 서킷브레이커가 그 경우의 안전장치입니다.

## 최적화 대상과 포기한 것

부분 오류 상황에서 **가용성**을 지키는 것을 택했습니다. 대신 받아들인 것:

- "일부 행이 빠진 채 서빙될 수 있다"는 상태를 허용한다
- 그래서 **격리 로그를 남겨 사후 추적**이 가능하게 했다 — 어떤 행이 왜 빠졌는지 확인할 수 있어야 이 선택이 정당하다

## 검증 방법

- 의도적으로 오염된 행을 넣었을 때 정상 행은 적재되고 오염 행만 격리되는지
- 실패율이 임계치를 넘으면 적재가 중단되는지

## 재검토 조건

**격리율이 상시 높게 유지되면** 이는 상류 품질 문제입니다. 격리로 버티지 말고 원인을 고쳐야 합니다. 격리는 예외 처리 장치이고, 정상 상태의 일부가 되면 안 됩니다.
